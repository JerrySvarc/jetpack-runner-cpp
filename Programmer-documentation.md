# Jetpack Runner - Programming guide

## Project structure

```
├───packages
│   ├───SFML-cpp.2.5.1
├───Resources
├───Source
├───JetpackRunner.sln
├───CMakeLists.txt
```

The project was mainly developed in Visual studio 2022. For this reason, the provided .sln file is the main way of opening and building the project in Visual studio. The required SFML library is included in the project usign a Nuget package. It is not the only way of building the project. A CMakeLists.txt is also provided and it allows developers to use CMake to build the project. This comes with the caveat that the developer must install the development version of SFML to their system, otherwise the compilation will fail.

All source files are located inside the Source/ folder. By source files we mean .cpp and .h files. 

The Resources/ folder contains all graphical sprites needed for the game. It also contains a font file needed to display messages in the game.


## Source code explained

This will serve as a surface level explanation of the source code structure for the game. It is not meant to explain to you all the intricacies of the implementation(the code is not that complex and should be easy to figure out just by looking at it directly). It is meant to introduce you to the meaning behind the most important methods.

### Game
This is the main class for the game. It contains all the necessary information needed to run the game. It contains all constant used throughout the game, instances of the many different entities, all methods instantiating and managing the different game components and the game loop itself. 

- Most important methods:
    - Game::run() - Starts the game loop. Game first initializes the player, zappers and the background. Then it enters a while loop while detecting events generated by the user. The loop consists of calculating the movement of the player, zappers and the background changing their positions inside the window, detecting any collisions
    and changing textures to animate the sprite. If the player runs into a zapper, the game can be restarted by pressing 'R' on their keyboard. The loop updates every 15 ms.
    - Game::init_game() - Game initialization consists of initiliazing the player, the sfml window, background, zappers, coins and the reverser entites. It also initializes the text shown inside the window displaying the number of collected coins.
    - Game::reset_game() - Resets all entities. 
    - Game::check_collision() - Checks collision between the specified entities. 
    - Game::animate_entities - Provides animation for all the different entites. Animation is the result of changing the between different textures for each sprite.
    - Game::render() - Render all the window components using methods provided by SFML.

### Entity
This class represents an entity which can be rendered to the SFML window. It contains a collection of different textures. It also contains the sprite to which we can apply the diffent texture. 

- Methods:
    - Entity::add_texture(const std::string& file_name) - Method used to add a new texture to the collection of textures for the given entity.
	- Entity::change_sprite_texture(unsigned int index) - Method used to change the texture of the sprite. It is given a index where the texture should be located inside the collection.
	- Entity::modify_textures(unsigned int index, const std::string& file_name) - This method is used to change a texture inside the collection. It loads the new texture and puts it inside the collection at the specified index. 

### Item
This class represents an item. Item is a thing which can have a certain effect on the game. This class serves as an interface. Classes inhereting from it must implement the following methods. 
- Methods:
    - virtual void affect_game(Game &game) = 0 
    - virtual void reset_effect(Game &game) = 0

### Player 
This class represents the player entity.

### Zapper 
This class represents the zapper entity.

### Coins
This class inherits from Entity and Item classes. When the coin's sprite intersects with the player sprite, it adds 1 to the coins_ variable inside the Game class.

### GravityReverser
This class inherits from Entity and Item classes. When the reversers's sprite intersects with the player sprite, it changes the player's sprites and it also changes the behaviour of the game. The gravity is reversed.
